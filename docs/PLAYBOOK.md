# پیاده‌سازی مرحله‌به‌مرحله — دستورهای تست برای کاربر

این فایل فقط برای «چطور کدها را به‌روز کنم و کجا ببینم» است. هیچ دستوری اینجا لازم نیست حفظ شود؛
در پایان هر فاز، دقیقاً همان دستورهای لازم در چت نوشته می‌شود.

## ۰) روش درستِ گرفتن آخرین کد (مهم‌ترین بخش همین فایل)

**همیشه روی `main` بمان.** برنچ‌های `phase-XX-...` فقط برای بایگانی‌اند و ممکن است قدیمی باشند؛
اگر روی آن‌ها باشی، `git pull` کدِ قدیمی همان برنچ را می‌آورد و فکر می‌کنی چیزی تغییر نکرده است.
(این دقیقاً همان چیزی بود که در QA فاز ۳ اتفاق افتاد.)

در پنجره‌ی PowerShell داخل پوشه‌ی پروژه، این پنج خط را به‌ترتیب بزن:

```powershell
git fetch origin
git checkout main
git reset --hard origin/main
git log --oneline -1
npm install
```

خروجی `git log --oneline -1` باید **دقیقاً** همان هَشِ کوتاهِ کامیتی باشد که در چتِ همان فاز
نوشته می‌شود (مثلاً `9f1c2ab`). اگر فرق داشت، یعنی کدِ جدید را نگرفته‌ای و هیچ تغییری هم در
مرورگر نخواهی دید.

بررسی دوم (بدون شک): بعد از `npm run dev`، در **پایینِ هر صفحه** یک برچسب کوچک هست که
«فاز/تاریخ» و هَشِ کامیت را نشان می‌دهد. اگر آن برچسب، متنِ وعده‌داده‌شده در چت نبود → چک‌اوت قدیمی
یا کشِ قدیمی است؛ این را بزن و دوباره `npm run dev`:

```powershell
Remove-Item -Recurse -Force .next
```

**نشانه‌ی کشِ قدیمی:** در پایین همین PowerShell نوشته شود
`⚠ Port 3000 is in use ... using available port 3001` — یعنی یک `npm run dev` دیگری از قبل روشن است
و مرورگر تو آن سرویس قدیمی را نشان می‌دهد، نه کدِ تازه. آن پنجره‌ی قدیمی را با `Ctrl` + `C` ببند
(یا سیستم را یک بار restart کن) و دوباره `npm run dev` بزن تا آدرس `http://localhost:3000` را بگیرد.

## ۱) به‌روزرسانی کدها (هر بار که فاز جدیدی تمام شد)

در پوشه‌ی پروژه (روی ویندوز: کلید `Shift` را نگه‌دار، راست‌کلیک روی فضای خالی پوشه →
«Open PowerShell window here» / «باز کردن پنجره‌ی اینجا»):

```powershell
git fetch origin
git checkout main
git reset --hard origin/main
npm install
Remove-Item -Recurse -Force .next
```

اگر `npm install` چیزی نصب نکند، فقط یک خط ساده نشان می‌دهد و تمام — این طبیعی است.
`Remove-Item ... .next` کشِ بیلد را پاک می‌کند؛ بدون آن ممکن است `npm run dev` نسخه‌ی قبلی را
نشان بدهد و به‌نظر برسد تغییری انجام نشده است.

برای اطمینان از اینکه فایل‌های فاز جدید واقعاً در این پوشه‌اند (نام فایل را از چت همان فاز بردار):

```powershell
Test-Path src\services\wallet\mock.ts
```

خروجی `True` یعنی فایل هست؛ `False` یعنی کد در همین پوشه نیست (پوشه را اشتباه باز کرده‌ای یا
pull land نشده). روی مک/لینوکس: `ls src/services/wallet`.

## ۲) بالا آوردن پروژه

```powershell
npm run dev
```

وقتی این خطوط را دیدی یعنی آماده است:

```
▲ Next.js 15.5.25
- Local: http://localhost:3000
✓ Ready in ...
```

برای خاموش کردن: در همان پنجره کلیدهای `Ctrl` + `C`.

## ۴) قاعده‌ی رفرش

بعد از هر بار `git pull`، در مرورگر یک بار `Ctrl` + `Shift` + `R` بزن (ریفرش کامل).
اگر صفحه سفید یا خطا داد، `npm run dev` را با `Ctrl` + `C` ببند و دوباره باز کن.
اگر باز هم درست نشد، این دو خط را بزن و دوباره `npm run dev`:

```powershell
Remove-Item -Recurse -Force .next
npm run dev
```

## ۵) زبان را کجا عوض کنم؟

دکمه‌ی `EN | فارسی` در گوشه‌ی چپِ نوار بالای صفحه (حالت فارسی: گوشه‌ی راست) است. یک بار کلیک کن؛
صفحه با همان مسیر ولی در زبان دیگر باز می‌شود و انتخابت در کوکی ذخیره می‌شود، پس اگر آدرس
`http://localhost:3000` را تنهایی هم باز کنی، همان زبان را می‌بینی.

## ۶) هر بار که فازی تمام شد، چه چیزی در چت می‌نویسم؟

پنج چیز، همیشه:
1. چه چیزی ساخته/اصلاح شده (فارسی ساده).
2. **هَش کوتاه کامیت و متن برچسب فاز** که باید در پایین صفحه ببینی (تا معلوم شود کدِ تازه را گرفتی).
3. دستورهای دقیق: `git fetch` / `git checkout main` / `git reset --hard origin/main` →
   `npm install` → پاک‌کردن `.next` → `npm run dev`.
4. آدرس یا آدرس‌هایی که باید باز کنی و آنچه باید در هر کدام ببینی.
5. **جدول چک‌لیست**: هر بندِ قابل‌تست در یک ردیف، با «کجا را ببینی» و «چه چیزی نشانه‌ی قبولی است».
   هر ردیفی که در این جدول نباشد، یعنی در آن فاز ساخته نشده — پس اگر موردی را جا افتاده دیدی،
   همان شماره‌ی ردیف را بگو.
